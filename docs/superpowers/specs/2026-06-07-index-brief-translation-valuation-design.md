# 美股指数简报中文化与估值模块设计

## 背景

当前每日简报已经能在 GitHub Actions 中生成并发送到 Gmail，但存在三个需要改进的问题：

- 邮件中的“查看完整报告”链接指向 GitHub Pages。仓库为私有仓库，当前 GitHub 方案不支持为其发布 Pages，因此链接返回 404。
- 未配置外部 LLM API Key 时，规则结论仍为中文，但新闻标题和摘要会退回英文。
- 报告只有价格、回撤和波动指标，缺少用于长期观察的估值信息。

本次改造保持仓库私有，并以“邮件本身就是完整报告”为原则，不新增公开网站或新的付费账户。

## 目标

- 新生成的邮件不再包含任何 GitHub Pages 或“查看完整报告”链接。
- 使用 GitHub Models 将入选新闻的标题、要点和市场关联说明生成中文。
- 展示纳斯达克100和标普500的官方预期市盈率数据及其长期均值比较。
- 严格区分 PE 估值、价格位置和回撤，不用价格百分位冒充 PE 百分位。
- 翻译或估值数据不可用时，仍能发送包含核心行情和规则结论的降级报告。

已发送的旧邮件无法远程修改，因此旧邮件中的 404 链接会继续存在；本设计只保证后续生成的邮件不再出现该链接。

## 方案选择

### 完整报告

采用私有仓库加完整邮件正文的方案。邮件继续使用移动端单栏 HTML，所有行情、估值、新闻和风险提示均在正文中呈现。

`gh-pages` 分支可继续作为历史报告和 `.emailed` 投递状态的私有存储，但不再被视为可访问的网站。工作流不再生成公开站点入口，也不读取或拼接 `REPORT_BASE_URL`。

### 中文翻译

采用 GitHub Models，而不是非官方免密 Google 翻译接口。GitHub Actions 使用内置 `GITHUB_TOKEN`，增加最小权限 `models: read`，无需用户创建新的 API Key。

模型名称通过环境变量配置，并选择 GitHub Models 目录中可用的轻量模型作为默认值。翻译请求采用单次批量结构化输出，减少调用次数和限额消耗。

### 估值数据

第一阶段使用 Nasdaq 官方发布的 Global Index Investment Insights 数据。该资料同时提供纳斯达克100和标普500的预期 PE、10 年平均预期 PE，以及当前值相对均值的偏离。

不接入来源和定义不透明的即时“历史 PE 百分位”。每次遇到新的官方估值数据日期时保存一条快照；相同数据日期不得因每日运行而重复写入历史样本。

## 报告内容

### 核心行情

保留现有两大指数的收盘点位、单日涨跌和 60 日回撤，并保留 VIX、美国 10 年期国债收益率和美元指数等可用补充数据。

### 估值观察

每个指数显示：

- 当前预期 PE。
- 10 年平均预期 PE。
- 当前 PE 相对 10 年均值的溢价或折价百分比。
- 估值数据对应日期。
- 估值温度：`低于长期均值`、`接近长期均值`、`高于长期均值`或`明显高于长期均值`。

估值温度使用固定规则生成，不交由模型自由判断：

- 相对 10 年均值不高于 `-10%`：`低于长期均值`。
- 高于 `-10%` 且不高于 `+10%`：`接近长期均值`。
- 高于 `+10%` 且不高于 `+25%`：`高于长期均值`。
- 高于 `+25%`：`明显高于长期均值`。

估值只作为长期观察信息，不改变现有基于跌幅、回撤和波动生成的定投建议等级。

### PE 百分位

第一阶段不显示 PE 百分位。系统按官方数据日期积累去重后的月度快照：

- 至少有 36 个不同月份的有效样本后，才可显示明确标注的“近 3 年 PE 百分位”。
- “近 10 年 PE 百分位”必须拥有至少 120 个不同月份的有效样本。
- 样本不足时显示“历史样本积累中”，不得输出估算百分位。

百分位功能属于后续阶段，本次只建立可延续的数据存储格式。

### 中文新闻

每条入选新闻展示：

- 中文标题。
- 一至两句中文要点。
- `直接事实`或`可能相关`标签。
- 原始新闻链接和来源名称。

模型只能使用输入中的新闻和链接，不能创建新来源，不能把“可能相关”改写成确定因果，也不能修改规则生成的定投观察。

## 组件变更

- `valuation.ts`：下载、解析和校验官方估值资料，输出结构化估值快照。
- `valuation-history.ts`：按官方数据日期保存和读取去重后的估值历史。
- `commentary.ts`：通过统一的评论接口调用 GitHub Models，要求所有展示文本为中文。
- `github-models.ts`：封装 GitHub Models 请求、超时、结构校验和错误信息，不记录令牌。
- `render.ts`：加入估值区块和数据日期，移除完整报告链接及相关渲染参数。
- `run.ts`：在行情之后加载估值；估值失败时继续生成报告。
- GitHub Actions：增加 `models: read` 权限和 `GITHUB_TOKEN` 环境变量，删除 Pages 地址配置的使用。

现有完整 HTML 文件仍作为私有归档生成，但内容与邮件一致，不承诺存在公网访问地址。

## 数据流

1. GitHub Actions 在既定时间触发并恢复私有历史报告与投递状态。
2. 获取并校验两大指数行情；核心行情失败则终止正常日报。
3. 获取相关新闻并筛选最近且与指数相关的项目。
4. 获取官方估值资料，校验数据日期和数值范围；若发现新日期则保存快照。
5. 规则引擎根据行情生成定投观察。
6. GitHub Models批量生成中文复盘、新闻标题和要点。
7. 渲染包含全部内容的移动端邮件与私有归档 HTML。
8. 发送邮件，成功后写入 `.emailed` 标记并持久化报告状态。

## 数据校验与时效

- 预期 PE 和 10 年均值必须为有限正数，并处于合理的指数估值范围内。
- 两个指数的数据必须来自同一期官方资料，并保留资料的 `as of` 日期。
- 官方数据日期距离报告生成日超过 45 天时，估值区块不展示具体数值，改为“官方估值数据暂未更新”。
- 解析结果不完整、字段重复冲突或无法确认口径时，本次估值加载失败，不使用上一次数值伪装成最新数据。
- 报告中明确标注估值为定期发布数据，不暗示其与昨夜收盘价同步。

## 降级行为

### GitHub Models 不可用

- 行情、规则结论和估值区块继续生成。
- 总结使用现有确定性中文模板。
- 新闻保留原文标题和链接，并显示“中文翻译暂不可用”。
- 模型失败不导致整封邮件失败。

### 估值资料不可用

- 不展示 PE、均值、溢价或温度。
- 显示“官方估值数据暂不可用”，其余报告正常发送。
- 失败数据不得写入估值历史。

### 私有状态存储失败

- 在无法可靠读取投递状态时，不盲目发送，以避免重复邮件。
- 邮件发送成功但状态持久化失败时，工作流明确失败并保留诊断信息，后续人工核对后再重试。

## 安全与权限

- 工作流权限限制为 `contents: write`和`models: read`。
- GitHub Models 只接收公开行情和新闻文本，不发送 Gmail 凭据、收件地址或应用专用密码。
- `GITHUB_TOKEN`、Gmail 应用专用密码和其他 Secret 不写入日志、报告或构建产物。
- 外部新闻文本在写入 HTML 前继续进行转义，链接只允许 `http`和`https`。

## 测试与验收

### 自动测试

- 邮件 HTML 不包含“查看完整报告”、`REPORT_BASE_URL`或 GitHub Pages 链接。
- GitHub Models 正常返回时，标题、摘要和新闻解释均为非空中文，并只保留输入中的 URL。
- GitHub Models 超时、限流、返回非 JSON 或缺字段时进入确定性降级流程。
- 估值解析覆盖正常资料、字段缺失、异常数值、不同期数据和超过 45 天的过期资料。
- 相同官方数据日期重复运行不会增加估值历史样本。
- 估值温度边界值和溢价计算具有独立单元测试。
- 估值失败不会改变定投建议，也不会阻止邮件生成。

### 工作流验收

- 在 GitHub Actions 中确认 `models: read` 可以使用内置 `GITHUB_TOKEN`完成一次中文生成。
- 手动运行一次工作流并检查手机 Gmail：正文完整、中文新闻可读、估值日期清楚、没有 404 链接。
- 检查报告归档和 `.emailed` 标记仍能防止同一交易日重复发送。
- 验收邮件发送成功后，继续保留每日北京时间约 08:05 的现有计划任务。

## 非目标

- 不把仓库或报告改为公开。
- 不使用非官方免密 Google 翻译端点。
- 不购买或接入付费历史估值数据库。
- 不把估值温度直接转换为买卖或加减仓指令。
- 不追踪某一家境内基金的净值、额度、申购状态或汇率结算结果。
- 不修复已经发送邮件中的旧链接，因为邮件内容无法远程更新。
